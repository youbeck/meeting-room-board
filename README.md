# 會議室預約看板

小團隊共用 3 間會議室的單日預約看板。一眼看出各時段是否有空，並可快速預約、修改、取消。純前端、零依賴，用瀏覽器開啟即可使用。

> **資料限制**：預約資料存在瀏覽器的 `localStorage`，僅限同一台電腦的同一個瀏覽器，**不會跨使用者或跨裝置同步**。清除網站資料後，預約會消失（頁面仍可正常開啟，顯示全空網格）。

## 功能清單

- **單日網格**：橫軸 09:00–18:00（9 個 1 小時時段）、縱軸 3 間會議室。
- **日期切換**：前後切換日期（自動略過週末）、「回到今天」；若開啟當天是週末，會顯示下一個平日。
- **預約**：先點起始格、再點結束格（同會議室、同一天，可連續多小時），起訖之間皆空才會跳出輸入視窗；「姓名」與「會議主題」皆必填。連續時段存為一筆，格子合併顯示。
- **修改／刪除**：點已預約的格子或列表中的按鈕。需輸入預約時的姓名（防誤刪用，**不是安全機制**）。可改時間、姓名、主題（日期與會議室不可改）；修改時的衝突檢查會排除自己。
- **預約列表**：網格下方列出所有日期的預約，每筆可修改／刪除。
- **匯出 CSV**：匯出目前選定日期的預約（會議室、時段、預約人）。
- **規則檢查**：同會議室同時段不可重複；僅可預約今天起 14 天內的平日；已過的時段不可預約。
- **狀態顏色**：空位／已預約以顏色區分，過去與不可預約的時段呈灰階。
- 桌面瀏覽器為主要目標，手機版為加分項。

非目標：週／月視圖、週末與非營業時段、重複預約、通知、會議室編輯、登入與權限角色。

## 如何開啟使用

不需安裝、不需建置。

1. 取得專案後，直接用瀏覽器開啟 `index.html`（雙擊或拖進瀏覽器）。
2. 若瀏覽器在 `file://` 下限制 `localStorage`，改用本機靜態伺服器，例如在專案目錄執行：

   ```bash
   python -m http.server 8000
   ```

   再開啟 <http://localhost:8000/index.html>。

基本操作：點空格作為起點 → 點另一格作為終點（同一格即 1 小時）→ 填姓名與主題送出。

## 如何執行測試

沒有測試框架或指令，測試是一個獨立的頁面：用瀏覽器開啟 `test.html`（同樣建議經 `localhost`）。

頁面會載入 `app.js`，針對 `findBooking` 的衝突判斷跑一組案例（完全相同、部分重疊前後段、完全包含、緊鄰、不同會議室、不同日期等），並在頁面頂端顯示總結（全部通過為綠色、有失敗為紅色），下方表格列出每個案例的預期與實際結果。

## 檔案結構

| 檔案 | 說明 |
| --- | --- |
| `index.html` | 主程式：介面、樣式與主要邏輯（含 `localStorage` 存取、預約流程、CSV 匯出）。 |
| `app.js` | 共用的預約衝突判斷（`findBooking`），以一般 `<script src>` 載入、函式為全域；`index.html` 與 `test.html` 共用。 |
| `test.html` | 衝突檢查的瀏覽器測試頁。 |
| `spec.md` | 規格與驗收標準，修改功能前請先閱讀。 |
| `CLAUDE.md` | 給 Claude Code 的專案指引與開發規範。 |
| `bugs.md` | 已知問題的點交紀錄。 |

## 開發規範

- 程式檔案限 `index.html` + `app.js` + `test.html` 三檔，不再拆分其他檔案、不使用外部框架，`app.js` 不用 ES module。
- 介面文字與程式註解使用繁體中文。
- 以 `spec.md` 為準；修改後請確認驗收標準仍成立，並以 `test.html` 驗證衝突檢查。

## 資料格式

`localStorage` 的 key 為 `meetingRoomBookings`，內容為物件，鍵為 `日期|會議室|起始小時`（如 `2026-01-05|A|10`），值為 `{ name, topic, hours }`，其中 `hours` 為連續時數。
